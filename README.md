# PIXO — конструктор SVG-композиций

React/Vite-приложение для сборки композиций только из существующих SVG-компонентов. Оно не создаёт новые рисунки и не растеризует элементы при экспорте.

## Запуск

```sh
npm install
npm run dev
```

`npm run build` собирает production-версию. `npm run lint` запускает Oxlint.

## Каталог для локальной работы и публикации

Вкладка «Библиотека» принимает отдельные SVG-файлы или пакет JSON. Импортированные данные сохраняются в IndexedDB текущего браузера. Для проверки в другом браузере или после публикации экспортируйте пакет кнопкой «Скачать библиотеку» и положите его как `public/library.json`. Приложение загружает этот каталог при запуске и объединяет его с локально добавленными компонентами.

`public/library.json` уже заполнен компонентами из переданных SVG-листов: 10 главных и 10 фоновых объектов, каждый в вариантах L и S (всего 40 SVG-компонентов), а также тремя цветовыми схемами. Оригинальные листы сохранены в `public/source/illustration-L.svg` и `public/source/illustration-S.svg`. Поскольку экспорт из Figma содержит плоский набор контуров без групп и имён компонентов, `scripts/build_library_from_source_sheets.py` разделяет его по координатным областям исходных листов. Контуры остаются векторными; изображения не растрируются и не создаются заново. После обновления листов каталог можно пересобрать той же командой.

Пакет имеет версию `1` и содержит `assets` и необязательный массив `palettes`. Каждый компонент хранит SVG-разметку, `viewBox`, размеры, роль `main`/`background`, `familyId`, размер `S`/`L`, теги и имя исходного файла. Имена файлов вида `book-S.svg` и `book-L.svg` автоматически связываются в семейство `book`; метаданные можно исправить в свойствах библиотеки. Для каждого семейства приложение показывает, загружены ли оба размера.

При импорте папки роль и размер также читаются из структуры каталогов. Удобная схема: `main/S/book.svg`, `main/L/book.svg`, `background/S/book.svg`, `background/L/book.svg`. Папки `фон` и `background` задают фоновую роль; `S`/`small` и `L`/`large` задают детализацию. Имена вложенных тематических папок и файлов становятся поисковыми тегами.

## Подбор и сборка

Режим «По объектам» ищет названия и теги. Режим «По метафоре» ранжирует те же исходные компоненты по тегам, названию, категории и локальному словарю связанных понятий; простой разбор словоформ помогает находить русские склонения. После сборки показываются выбранные компоненты и причина совпадения. Выбор S/L фильтрует именно исходный вариант нужной детализации, а не масштабирует другой файл. Новые элементы в процессе не создаются. Это объяснимый локальный подбор, а не подключённая генеративная AI-модель.

Примеры запросов для режима «По объектам»:

- `книга, смартфон, пазл` — сцена про обучение и цифровые инструменты;
- `наушники, настольная лампа, цветы` — сцена рабочего места и музыки;
- `монета, блокнот, карандаш` — сцена планирования бюджета.

Автораскладка учитывает формат и роль: первый подходящий главный объект становится визуальным центром, остальные размещаются как поддерживающие элементы, фоновые — как небольшие акценты по краям. Переключатель формата доступен над холстом и в свойствах. Автораскладка адаптируется под горизонтальный, квадратный или вертикальный холст; если пользователь уже перемещал объекты, редактор вписывает его ручную раскладку, сохраняя относительные позиции и пропорции. Переключатель S/L подменяет SVG каждого объекта на парный исходный файл, сохраняя его экземпляр и положение; контуры исходников не редактируются, меняются только масштаб экземпляра и отображение палитры. Если пары не хватает, переключение блокируется, чтобы не смешивать детализации. После сборки объекты можно перемещать и масштабировать мышью с сохранением пропорций, поворачивать, дублировать, удалять и менять местами в слоях.

## Палитры

В комплект включены три схемы из переданных листов: «Лавандовая», «Персиковая» и «Мятная». Новые палитры можно загрузить JSON-файлом. Если файл не содержит карт, приложение автоматически сопоставляет цвета по слотам исходной схемы; явные карты из файла имеют приоритет. Фоновая роль использует только цвета фона, главная — цвета объектов и фона. Интерфейс и экспорт проверяют допустимые назначения; если в карте нет исходного цвета, выбирается ближайший разрешённый оттенок. Исходная разметка SVG при этом не перезаписывается. Карту можно уточнить в свойствах палитры.

```json
{
  "name": "Название схемы",
  "objectColors": ["#E884A8", "#6B4EE8"],
  "backgroundColors": ["#DCCFF5", "#BBA6EA"],
  "objectColorMap": {"#FF0000": "#E884A8"},
  "backgroundColorMap": {"#00FF00": "#DCCFF5"}
}
```

В примере `#FF0000` и `#00FF00` — условные исходные цвета. Для библиотеки из задания используются уже подготовленные исходные карты. Для другой SVG-библиотеки проверьте и при необходимости настройте карту цветов в приложении после импорта. Перекраска применяется только к значениям `fill`, `stroke` и цветовым CSS-свойствам: она не ищет HEX по всему тексту SVG, поэтому не портит CSS ID, градиенты и ссылки на маски. Фоновые элементы не получают цвета из палитры главных объектов.

## Хранение и экспорт

В IndexedDB (`pixo-workspace`) хранятся библиотека, сцена, палитры и настройки. Экземпляр композиции ссылается на компонент через `assetId`; координаты и поворот хранятся отдельно. Исходная SVG-разметка при перекраске не изменяется. Экспорт формирует SVG с точным размером холста, уникализирует внутренние ID каждого экземпляра и сохраняет объекты как редактируемые векторные группы.

Основные модули: интерфейс — `src/ComposerStudio.tsx`; подбор, цветовые карты и раскладка — `src/features/composer/composer.ts`; очистка импорта — `src/features/svg-import/SvgSanitizer.ts`; локальное хранение — `src/features/storage/workspaceStorage.ts`; экспорт — `src/features/export/SvgExporter.ts`.

## Границы текущей версии

- В приложении нет внешнего AI-вызова или backend. Подбор метафоры — локальные правила, поэтому точность зависит от названий и тегов исходных компонентов.
- Данные остаются локальными в браузере, если их не включить в `public/library.json`. Облачная синхронизация и общая библиотека не настроены.
- Выделение компонентов из листов основано на их текущем расположении в SVG. Если макет исходного листа изменится, координатные области нужно обновить в скрипте сборки библиотеки.
- OpenAI Codex использовался при разработке. Само приложение не отправляет данные в AI-сервисы.
